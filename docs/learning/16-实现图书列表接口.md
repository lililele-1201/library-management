# 第 16 节：测试驱动实现图书列表接口

## 一、本节目标

这一节只实现图书列表接口：

```text
GET /api/books
```

完成后：

- 数据库没有图书时返回 `[]`。
- 数据库有图书时返回图书数组。
- 可以直接在浏览器中访问接口。

本节不实现单本详情、排序、分页、搜索、修改或删除。

## 二、为什么上一节浏览器显示 Cannot GET

第 15 节只实现了：

```text
POST /api/books
```

浏览器地址栏默认发送 `GET` 请求，当时没有对应的 `@Get()` 方法，因此 Nest 返回：

```text
Cannot GET /api/books
```

本节添加 `GET /api/books` 后，同一个地址就可以直接在浏览器中打开。

## 四、Controller 添加 GET 路由

文件：`backend/src/books/books.controller.ts`

```ts
import { Body, Controller, Get, Post } from '@nestjs/common';

@Controller('books')
export class BooksController {
  constructor(private readonly booksService: BooksService) {}

  @Get()
  findAll(): Promise<Book[]> {
    return this.booksService.findAll();
  }
}
```

### 1. @Get()

```ts
@Get()
```

它告诉 Nest，下面的 `findAll()` 方法处理 GET 请求。

三个路径部分组合起来：

```text
全局前缀              api
@Controller('books')  books
@Get()                没有额外子路径
                      ↓
GET /api/books
```

### 2. findAll()

```ts
findAll(): Promise<Book[]> {
  return this.booksService.findAll();
}
```

`Book[]` 表示 Book 对象数组，`Promise<Book[]>` 表示数据库查询完成后得到 Book 数组。

Controller 不直接查询数据库，只把任务交给 Service。

### 3. 为什么没有 @Body()

列表查询不需要客户端提交图书数据，因此没有请求体，也不需要 `CreateBookDto`：

```text
POST /api/books -> 需要 @Body() 和 CreateBookDto
GET  /api/books -> 不需要请求体
```

### 4. 为什么没有手动设置 200

Nest 中 `@Get()` 成功时默认返回：

```text
200 OK
```

所以不需要额外添加 `@HttpCode(200)`。

## 五、Service 查询所有图书

文件：`backend/src/books/books.service.ts`

```ts
findAll(): Promise<Book[]> {
  return this.bookRepository.find();
}
```

`bookRepository` 是第 11 节注入的：

```ts
@InjectRepository(Book)
private readonly bookRepository: Repository<Book>
```

TypeORM 的 `find()` 会查询 `book` 表中的所有记录。

可以简单理解成类似的 SQL：

```sql
SELECT * FROM book;
```

本项目没有手写 SQL，TypeORM 会根据 `Book` Entity 生成查询。

## 六、空数据库为什么不需要特殊判断

当数据库中没有图书时：

```ts
await this.bookRepository.find();
```

TypeORM 自然返回：

```ts
[]
```

因此不需要写：

```ts
if (没有数据) {
  return [];
}
```

也不应该因为列表为空返回 `404`。列表接口成功执行但没有数据，正确结果就是：

```text
HTTP 200
[]
```

## 七、完整调用链

客户端或者浏览器请求：

```text
GET http://localhost:3000/api/books
```

服务端执行：

```text
Nest 收到 GET /api/books
  -> 根据路由找到 BooksController.findAll()
  -> BooksController 调用 BooksService.findAll()
  -> BooksService 调用 Repository<Book>.find()
  -> Repository 通过 DataSource 使用已有数据库连接
  -> sqlite3 查询 SQLite 的 book 表
  -> TypeORM 把查询结果转成 Book 对象数组
  -> Service 返回数组
  -> Controller 返回数组
  -> Nest 转成 JSON
  -> 客户端收到 200
```

最简调用链：

```text
GET
-> Controller.findAll()
-> Service.findAll()
-> Repository.find()
-> SQLite
```

## 十三、常见误区

### 1. 认为 GET 也需要 CreateBookDto

列表接口没有请求体，不需要新增 DTO。

### 2. 空列表返回 404

请求成功但没有数据时应返回 `200` 和 `[]`。`404` 通常用于查询某个具体 ID 但没有找到。

### 3. 在 Controller 直接调用 Repository

Controller 继续只负责 HTTP，数据库查询由 Service 通过 Repository 完成。

### 4. 把 find() 和 findOneBy() 混淆

`find()` 查询多条记录；`findOneBy()` 查询一条记录。单本查询属于下一节。

### 5. 假设数据库默认返回固定顺序

本节没有指定排序，因此不要依赖数组顺序。后续如果产品需要固定顺序，应显式添加排序条件。

### 6. 提前添加分页和搜索

第一阶段暂不实现分页和搜索，本节只返回全部图书。

## 十四、本节验收标准

1. `GET /api/books` 路由存在。
2. Controller 调用 `BooksService.findAll()`。
3. Service 调用 `Repository<Book>.find()`。
4. 空数据库返回 `200` 和 `[]`。
5. 有数据时返回包含全部图书的数组。
6. 全部单元测试、端到端测试、lint 和构建通过。
7. 没有实现单本详情、排序、分页或搜索。

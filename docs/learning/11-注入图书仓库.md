# 第 11 节：将 Book Repository 注入 Service

## 本节目标

这一节只完成一件事：让 Nest 的依赖注入容器把 `Repository<Book>` 传给 `BooksService`。

## 二、Repository 是什么

Repository 可以理解为“一张表的数据管理员”。

```text
DataSource
  -> 整个数据库的总入口

Repository<Book>
  -> 只负责 Book Entity 对应的 book 表
```

后面会通过 Repository 提供的方法操作数据：

```typescript
bookRepository.find();
bookRepository.save(book);
bookRepository.remove(book);
```

这些只是后续会用到的例子，本节不调用它们。

## 四、在 BooksModule 注册 Repository

修改 `backend/src/books/books.module.ts`：

```typescript
import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { Book } from './book.entity.js';
import { BooksController } from './books.controller.js';
import { BooksService } from './books.service.js';

@Module({
  imports: [TypeOrmModule.forFeature([Book])],
  controllers: [BooksController],
  providers: [BooksService],
})
export class BooksModule {}
```

### `forFeature([Book])` 做了什么

`forFeature()` 接收当前功能模块需要使用的 Entity：

```typescript
TypeOrmModule.forFeature([Book])
```

它返回一个动态模块，内部为 Book 注册 Repository Provider。可以简化理解为：

```typescript
{
  provide: getRepositoryToken(Book),
  useFactory: (dataSource: DataSource) => dataSource.getRepository(Book),
}
```

实际过程：

```text
forFeature([Book])
  -> 确定当前模块需要 Book
  -> 从已有 DataSource 获得 Repository<Book>
  -> 使用 Book Repository token 注册这个对象
  -> BooksModule 内的 Provider 可以注入它
```

### 为什么放在 `imports`

`TypeOrmModule.forFeature([Book])` 返回的是配置好的动态模块，所以要放进 `BooksModule.imports`，不是放进 `providers`。

动态模块内部生成的 Repository 才是 Provider。

## 五、什么是 Repository token

Nest 的依赖注入容器需要一个标识来区分对象，这个标识叫 token（注入令牌）。

例如：

```text
BooksService token
  -> BooksService 实例

Book Repository token
  -> Repository<Book> 实例
```

`getRepositoryToken(Book)` 会生成 Book Repository 使用的 token。可以把容器理解成保存了：

```text
getRepositoryToken(Book)
  -> dataSource.getRepository(Book) 返回的对象
```

如果以后还有 `User` Entity，它会使用另一个 token：

```text
getRepositoryToken(Book) -> Repository<Book>
getRepositoryToken(User) -> Repository<User>
```

这样 Nest 不会把不同表的 Repository 混在一起。

## 六、将 Repository 注入 BooksService

修改 `backend/src/books/books.service.ts`：

```typescript
import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { Book } from './book.entity.js';

@Injectable()
export class BooksService {
  constructor(
    @InjectRepository(Book)
    private readonly bookRepository: Repository<Book>,
  ) {}
}
```

逐部分理解：

```typescript
@InjectRepository(Book)
```

告诉 Nest：这个构造器参数需要 Book 对应的 Repository token。

```typescript
private readonly bookRepository
```

- `private`：只在 `BooksService` 内部使用。
- `readonly`：构造完成后不能把它替换成另一个对象。
- `bookRepository`：Service 中保存这个依赖的属性名。

```typescript
: Repository<Book>
```

表示这个属性是专门操作 `Book` Entity 的 TypeORM Repository。

当前构造器没有函数体代码，因为 TypeScript 的参数属性语法会自动完成：

```text
接收构造器参数
  -> 保存到 this.bookRepository
```

## 七、Nest 实际如何完成注入

应用启动时：

```text
AppModule
  -> TypeOrmModule.forRoot(...)
  -> 创建并初始化 DataSource

BooksModule
  -> TypeOrmModule.forFeature([Book])
  -> DataSource.getRepository(Book)
  -> 注册 Book Repository token

Nest 创建 BooksService
  -> 读取 @InjectRepository(Book)
  -> 在容器中查找 Book Repository token
  -> 找到 Repository<Book> 实例
  -> 传入 BooksService 构造器
```

因此不需要自己写：

```typescript
new BooksService(dataSource.getRepository(Book));
```

对象的创建和传递由 Nest 容器负责。

## 八、移动 Entity 注册位置

第 10 节为了先验证表结构，在根配置中临时写了：

```typescript
entities: [Book]
```

本节已经在 `BooksModule` 中加入：

```typescript
TypeOrmModule.forFeature([Book])
```

而根配置从第 08 节开始就有：

```typescript
autoLoadEntities: true
```

所以现在的加载过程变为：

```text
BooksModule.forFeature([Book])
  -> 登记 Book Entity
  -> autoLoadEntities 收集 Book
  -> 根 DataSource 仍然认识 Book
```

因此从 `AppModule` 删除 `Book` 导入和 `entities: [Book]`，避免重复声明，也让 Book 留在图书功能模块中。`book` 表仍会正常同步。

## 九、修改 Service 测试

原测试只注册：

```typescript
providers: [BooksService]
```

现在 `BooksService` 多了必需依赖。如果测试不提供 Repository，Nest 会在 `.compile()` 时报告无法解析依赖。

测试中不需要连接真实数据库，因为本节只验证依赖注入关系。使用与真实环境相同的 token 注册一个空 mock：

```typescript
const bookRepository = {};

providers: [
  BooksService,
  {
    provide: getRepositoryToken(Book),
    useValue: bookRepository,
  },
]
```

各部分含义：

```text
provide: getRepositoryToken(Book)
  -> 注册时使用和 @InjectRepository(Book) 相同的 token

useValue: bookRepository
  -> 测试中用这个普通对象代替真实 Repository
```

当前 Service 没有调用任何 Repository 方法，所以空对象已经足够。以后开始 CRUD 时，会为 `find`、`save` 等方法添加 mock 函数。

测试能够创建 `BooksService`，就证明 Nest 已成功找到并注入 Repository 依赖。

运行聚焦测试：

```powershell
npm.cmd --prefix backend test -- books.service.spec.ts
```

## 十四、常见错误

### 1. 只写 `@InjectRepository(Book)`，没有 `forFeature([Book])`

注入装饰器只是在请求某个 token。如果模块没有注册这个 token，Nest 会报告无法解析 `BooksService` 的依赖。

### 2. 把 `Repository` 放进 `new`

不要自己写 `new Repository()`。Repository 需要使用已经初始化的 DataSource，应由 TypeORM 模块创建。

### 3. 在错误模块中注册

`BooksService` 属于 `BooksModule`，所以 Book Repository 也应在 `BooksModule.imports` 中注册。

### 4. 测试忘记提供 mock

Service 单元测试不会自动导入完整 `AppModule`。必须使用 `getRepositoryToken(Book)` 提供测试替身。

### 5. token 不一致

下面两处必须对应同一个 Entity：

```typescript
@InjectRepository(Book)
getRepositoryToken(Book)
```

如果其中一处写成其他 Entity，Nest 找不到正确依赖。

### 6. 提前调用 Repository 方法

本节只注入，不实现 CRUD。`find`、`save` 和 `remove` 会在后续独立节点按测试驱动方式加入。
